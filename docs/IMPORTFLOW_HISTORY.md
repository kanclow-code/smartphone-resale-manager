# ImportFlow 開発記録・これまでの経緯

最終更新: 2026-11-27

この文書は、ImportFlowが生まれた背景、開発中に確認したこと、構想が広がった経緯、今後も守りたい考え方を残すための記録です。単なる機能仕様書ではなく、プロジェクトの原点と判断の履歴を引き継ぐことを目的とします。

## 1. はじまり: 自分が欲しい道具を作る

ImportFlowの出発点は、Alibabaなどから商品を仕入れ、日本国内のフリマ・オークションサービスで販売する流れを、自分で無理なく管理したいという実用上の必要でした。

当初の対象はスマートフォン。仕入れ金額、為替、送料・税金などの輸入費用、在庫、販売先ごとの手数料、売上、入金、利益を一か所で追える道具を目指しました。

最初から大きな事業システムを作ろうとしたのではありません。「こういうことを代わりにやってくれる道具があったら便利なのに」という個人的な発想を、AIと一緒に実際に使える形へ変えていくことが原点です。

## 2. 初期の利用条件と事業イメージ

- 操作端末はAndroidスマートフォンのみ。PCでの作業を前提にしない。
- 当初はスマートフォンを月5〜10台ほど扱う小規模な輸入販売を想定。
- 販売先候補はメルカリ、PayPayフリマ、ヤフオク、楽天ラクマ。
- 仕入れ先としてAlibabaなどの海外調達先を想定。
- 仕入れ価格だけでなく、為替・国際送料・輸入税等を含む着地原価を把握する。
- 販売手数料、送料、その他費用、入金額を反映し、実際の利益を把握する。
- 取引中・未入金の売上を、確定した利益と混同しない。

この段階で重要になったのは、売上金額と実際に確定した利益を分けることでした。販売成立前・入金前の金額を利益として扱わない設計を重視します。

## 3. PWAとして形にする

PCを使わずスマートフォンだけで開発・利用を進められるよう、まずは単一HTMLを中心としたPWAとして構築しました。

- アプリ名: ImportFlow
- タグライン: 「輸入・在庫・販売・入金・利益を一元管理」
- リポジトリ: `kanclow-code/smartphone-resale-manager`
- GitHub Pages: https://kanclow-code.github.io/smartphone-resale-manager/
- 開発ブランチ: `chatgpt-write-test-20261126`
- GitHub Pagesは同ブランチのルートから配信する構成。
- Androidのホーム画面にPWAをインストールして利用。
- 現時点の基本構成はブラウザ内のlocalStorageにデータを保存する方式。クラウド同期は未実装。

開発では、スマートフォン上での操作負担を減らすこと、既存データを壊さないこと、少しずつ確認しながら進めることを優先します。

## 4. 実装してきた主な機能

### 仕入れ・輸入管理
- 仕入れ商品・仕入れ先の登録
- USD/JPY、為替レート、実際の支払額の記録
- Pay-easy等で表示された実支払額を入力するための上書き項目
- Alibaba注文番号、請求番号、支払日、支払状況
- 国際送料、税金、その他費用を含む仕入れ原価の管理
- 注文書・請求書等のOCR補助
- 為替レート取得補助

### 商品・在庫管理
- 商品情報、IMEI、シリアル番号、色、容量、状態、メモ
- 在庫・出品中・販売済み等の状態管理
- 在庫期間や値下げシミュレーション

### 販売・入金管理
- 販売先、販売日、販売価格の記録
- 販売手数料、送料、その他費用
- 取引中・入金済み・キャンセル等の状態管理
- 実際の入金額と入金日の記録
- キャンセル時に在庫へ戻し、再出品できる流れ

### 集計・データ管理
- 月次レポート
- 売上、原価、手数料・送料、利益、経費の集計
- 未入金・取引中の売上や仕入れ未払残高の区別
- 経費管理
- 仕入れ・在庫・販売・経費のCSV出力
- JSONバックアップと復元、復元前プレビュー、自動バックアップ
- 販売手数料の初期値設定
- 技適、PSE、輸入税・会計、販売サービス規約、IMEI等の確認チェックリスト

販売手数料の初期値として、メルカリ10%、PayPayフリマ5%、ヤフオク10%、楽天ラクマ10%を設定。実際の手数料は出品時点の各サービスの規約・条件に従って確認・入力する方針です。

## 5. 実データを使った確認と学び

2026年11月の確認では、バックアップからデータを戻し、仕入れ・販売・月次集計の表示を一つずつ確認しました。

確認時点のデータ例:
- 仕入れ4件、商品4件、販売2件、経費0件
- 販売の内訳はキャンセル1件、取引中1件
- 仕入れ4件の支払額は、0円/残高50,000円が3件、142,000円/残高0円が1件
- 仕入れ支払済み合計142,000円、未払残高合計150,000円
- 取引中のテスト販売は販売価格165,000円、原価142,000円、手数料16,500円、送料750円、計算上の利益5,750円
- キャンセル済みのテスト販売は販売履歴に「キャンセル」として表示され、在庫へ戻す処理を確認

月次レポートでは、取引中の165,000円を確定売上・確定利益に含めず、「取引中売上」として分けて表示することを確認しました。キャンセルされた販売は通常の売上・利益集計から除外する実装です。

この確認で得た重要な原則:
1. 売上と入金済み売上を分ける。
2. 取引中・未入金の金額は確定利益に含めない。
3. キャンセルは売上実績から除外し、商品を在庫に戻す。
4. 仕入れの総額、支払済み額、未払残高を分ける。
5. 利益は販売価格だけでなく、原価・手数料・送料等を反映して把握する。

JSONバックアップをダウンロードし、Androidのダウンロードフォルダに保存できることを確認。仕入れ・在庫・販売・経費の4種類のCSV出力も確認しました。復元機能の実地テストや複数端末間の同期は、まだ確認済みとは扱いません。

## 6. スマートフォン転売管理から、汎用的な販売管理へ

開発を進める中で、ImportFlowをスマートフォン専用に限定する必要はないという考えに発展しました。

将来的に扱いたい商品・取引の例:
- スマートフォン、タブレット、電子機器
- ポケモンカード等のトレーディングカード
- ガンプラ、ホビー、コレクション品
- 新品・中古品
- 海外からの輸入品だけでなく、国内仕入れ品
- 個人間の仕入れ・販売

目指すのは、個人や小規模事業者が、仕入れから商品登録、在庫、出品、販売、入金、経費、利益までを管理できる実務ツールです。輸入販売は最初の利用ケースであり、アプリの最終的な対象範囲ではありません。

## 7. AIで「面倒な作業」を減らす構想

将来の大きな価値は、単に記録を保存することではなく、面倒な作業をAIが肩代わりしてくれることにあります。

構想している機能:
- 商品写真から商品名・型番・特徴などを読み取る
- 商品情報やカテゴリ、状態の入力を補助する
- 商品説明・出品文を自動生成する
- 相場情報を調べ、販売価格や仕入れ上限の判断を補助する
- 手数料・送料・原価から利益や利益率を試算する
- 在庫期間や価格変動を見て、値下げ・販売戦略を提案する
- 仕入れ候補を比較し、調達判断を助ける

特に市場価格調査では、小売店の新品価格だけではなく、フリマ・オークション等の出品価格と売却済み価格を区別することが重要です。将来的には、中央値・最安値・最高値などを参考にできる仕組みを目指します。

外部サービスとの連携や自動出品は、各サービスの公式API・利用規約・技術的制約を確認したうえで検討します。すべてのサービスに自由に接続できることを前提にはしません。

## 8. デザインと使い心地

機能だけでなく、毎日使いたくなる見た目も大切にします。目指すのは、プロフェッショナルで、先進的で、個性のあるアプリです。

これまでに検討したデザイン方向:
- FUTURE TECH: 先進的・未来的・ダーク
- PREMIUM: 上質・洗練・落ち着き
- MODERN: ミニマル・美しさ・使いやすさ

アクセントカラー候補:
- アイスブルー／シアン
- バイオレット／パープル
- エメラルド／グリーン
- アンバー／オレンジ

ダークネイビーとシアンは有力候補として話題に上がりましたが、最終決定ではありません。4色の比較イメージを確認できるようになった段階で、実際の見た目を比べて選びます。

## 9. 開発の進め方として決めたこと

- すぐにGoogle Playで公開することを目標にしない。
- まず自分自身が日常的に使い、使いにくい点を見つけて改善する。
- 欲しい機能を思いついたら追加し、実際に使って検証するサイクルを続ける。
- 自分用として十分に優れたアプリへ育てる。
- その後、他の小規模販売者にも使えるように汎用化し、個別調整が少なくても使える段階で一般公開を検討する。
- すぐにネイティブAndroidアプリへ全面移行せず、まずは現在のPWAを改善する。
- 既存の機能やデータを守りながら、再利用しやすい構造へ段階的に整理する。
- 将来的にはImportFlowの基盤から、用途別の別アプリを展開できる可能性も残す。

## 10. 現在の技術的な注意点

- 現在のデータ保存先は利用端末・ブラウザ内のlocalStorage。クラウド同期は未実装。
- ブラウザや端末を変えた場合に自動でデータが共有されるわけではない。
- バックアップを定期的に取得し、安全に保管する。
- IMEI、シリアル番号、注文番号などを含む可能性があるため、バックアップやCSVの取り扱いに注意する。
- 既存データを消す操作や、localStorageを初期化する操作は安易に行わない。
- 大きな改修の前には、現行コードとデータのバックアップを確認する。
- 機能を追加するときは、仕入れ・在庫・販売・入金・利益の既存動作を壊していないか確認する。
- 市場価格や外部サービス連携は、データ取得方法・利用規約・精度・更新頻度を検証してから実装する。

## 11. これからの開発ロードマップ

### Phase 1: 自分で安心して使える基盤
- 現在の仕入れ・在庫・販売・入金・利益管理を安定させる
- バックアップと復元の安全性を高める
- スマートフォンでの操作性と画面デザインを改善する
- 入力ミスや状態の不整合を減らす

### Phase 2: 商品カテゴリの汎用化
- スマートフォン固有の項目と、全商品共通の項目を整理する
- トレカ、ホビー、電子機器、中古品などに対応する
- 国内仕入れと海外仕入れの両方を扱う

### Phase 3: 市場情報・価格判断
- 出品中価格と売却済み価格を区別する
- 商品ごとの相場、中央値、最安値、最高値を表示する
- 仕入れ上限、想定利益、値下げ判断を補助する

### Phase 4: AIアシスタント機能
- 写真からの商品認識
- 商品登録と出品文の作成補助
- カテゴリ・状態・価格の提案
- 仕入れ候補の比較と利益予測

### Phase 5: 外部連携と事業者向け機能
- 公式API等を使った連携可能性の調査
- データ同期や複数端末利用の設計
- 小規模販売者向けの設定・権限・運用機能

### Phase 6: 一般公開・派生アプリ
- 自分で使い込んで完成度を確認
- 汎用化とユーザーテスト
- 必要に応じてAndroidアプリ化・Google Play公開
- 共通基盤を活用した用途別アプリの検討

この順番は固定ではありません。実際に使って見つかった課題や、新しいアイデアに応じて更新します。

## 12. 変えずに残したい原点

ImportFlowは、最初から誰かのために作る大規模なサービスとして始まったわけではありません。

「自分が欲しい」「こうなったら便利」「こんなことまでできたら面白い」という自由な発想を、AIの力を借りて一つずつ現実にしていくプロジェクトです。

まず自分が本当に使いたいと思えるものを作る。使いながら発見し、直し、育てる。その積み重ねで、いつか同じ悩みを持つ人にも役立つ道具にする。

**人の自由な発想と、AIの幅広い知性を組み合わせて、新しく、面白く、使う人にとって自然で頼れる道具を生み出す。**

この考え方を、今後の機能追加・デザイン・技術選択・公開判断の基準として残します。
